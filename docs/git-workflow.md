# Git Branching & Workflow

This document describes how branches are used in this repository and how changes
flow from development to the live site.

## Branch overview

| Branch              | Purpose                                                                 | Buildable? | Deploys?                          |
| ------------------- | ----------------------------------------------------------------------- | ---------- | --------------------------------- |
| `main`              | **Production.** Source of the live GitHub Pages site.                    | Always     | Yes — auto-deploys to `gh-pages`  |
| `dev`               | **Integration.** Where test/work-in-progress code lands and is verified.| Always     | No                                |
| `topic/*`           | **Feature branches.** Isolated work (e.g. `topic/ui-redesign`).         | Not required | No                              |
| `gh-pages`          | **Build output only.** Generated by CI — do not edit by hand.           | n/a        | This *is* the deployed site       |

## How code flows

```
topic/ui-redesign  ──►  dev  ──►  main  ──►  gh-pages (live site)
   (feature work)     (test &     (prod)      (CI build output)
                       verify)
```

1. **Do feature work on a `topic/*` branch.** Branch off `dev`:
   ```bash
   git switch dev
   git switch -c topic/my-feature
   ```
2. **Merge into `dev` to integrate and test.** `dev` must always build
   (`npm run build` succeeds). Verify before merging up.
   ```bash
   git switch dev
   git merge topic/my-feature
   npm run build   # must pass
   ```
3. **Promote to `main` only when production-ready.** Pushing to `main`
   triggers a deploy, so only merge stable, tested code.
   ```bash
   git switch main
   git merge dev
   git push origin main   # triggers GitHub Pages deploy
   ```

## Branch rules

- **`main` is production.** Every push to `main` is built and published to the
  live site via the deploy workflow (see below). Never commit untested work here.
- **`main` and `dev` must always be buildable.** Run `npm run build` before
  merging into either.
- **Test/experimental code goes on `dev`** (or a `topic/*` branch), never
  directly on `main`.
- **`topic/*` branches** are for focused work and can be freely rebased or
  squashed before merging into `dev`.

## Deployment

Deployment is automated by `.github/workflows/deploy.yml`:

- **Trigger:** any push to `main` (or `master`).
- **Steps:** `npm install` → `npm run build` → publish the `dist/` folder to the
  `gh-pages` branch.
- **Result:** the contents of `gh-pages` are served as the live GitHub Pages site.

You do not deploy manually and you should never edit `gh-pages` directly — it is
overwritten by every successful build.

## Current branches

- `main` — production / live site.
- `dev` — integration and testing.
- `topic/ui-redesign` — in-progress UI redesign work.

## Quick reference

```bash
# Start new feature work
git switch dev && git switch -c topic/<name>

# Integrate a finished feature
git switch dev && git merge topic/<name> && npm run build

# Ship to production (auto-deploys)
git switch main && git merge dev && git push origin main
```
